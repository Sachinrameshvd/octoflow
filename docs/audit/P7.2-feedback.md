# OctoFlow P7.2 Audit & Swarm Feedback

Direct feedback, architectural limitations, and operational defects identified while dogfooding OctoFlow with local models (Ollama `qwen2.5-coder:7b`) to build the AI Resume Analyzer demo project (`examples/resume-analyzer/`).

## Identified Issues & Recommendations

### 1. Multi-Arm Role Cannibalization & Overlapping File Writes
- **Symptom**: During Mission 1, Arms 0 (Data), 1 (Model), 2 (Backend), and 6 (Security) all attempted to author `models.py`, overwriting each other's work and leaving `scoring.py` completely unauthored.
- **Root Cause**: The role prompt domain mappings in `octoflow/arm.py` did not strictly partition file ownership when a single objective mentions multiple files or concepts ("models.py" and "scoring.py").
- **Recommendation**: Conductor's task breakdown or arm role arbitration should explicitly assign primary file ownership tokens (e.g. `[assign: models.py -> Arm 0/1, scoring.py -> Arm 2]`).

### 2. Subdirectory Test Import Path Resolution
- **Symptom**: Generated test files in `examples/resume-analyzer/tests/` used top-level `from models import ...` instead of package-relative imports or inserting the example root into `sys.path` before imports.
- **Root Cause**: The QA Arm's code template assumes tests run from within the project directory rather than repo root with pytest discovery.
- **Recommendation**: QA Arm prompt or scaffold injection should always include `sys.path.insert(0, str(Path(__file__).resolve().parent.parent))` at the top of generated test suites.

### 3. Regressive File Overwrite in Incremental Missions
- **Symptom**: In Mission 2, Arm 1 (Model) completely deleted the clean Pydantic `models.py` authored in Mission 1, substituting a generic PyTorch neural network template.
- **Root Cause**: Arms do not check whether a file already contains verified, committed domain logic before proposing complete rewrites.
- **Recommendation**: Add a protective check in Arm sensory gating: if a file has previously committed code on git HEAD, require explicit modification (diff/patch) or prompt warning rather than wholesale overwrite.

### 4. QA Arm Synthetic Test Data Fallback
- **Symptom**: When tasked with writing tests for PDF parsing, Arm 5 passed invalid placeholder bytes `b'...'` instead of generating valid in-memory fixture files.
- **Root Cause**: Arm 5 lacked a standard library recipe for in-memory binary format fixtures (like `reportlab` or minimal PDF headers).
- **Recommendation**: Provide QA arm with domain-specific recipes for common binary formats (PDF, images, zip) in memory.

### 5. Module-Scope Hardware/Model Initializers
- **Symptom**: Arm 4 (Quantization) placed `ort.InferenceSession('path_to_your_model.onnx')` at top-level module scope, crashing import of unrelated utility functions.
- **Root Cause**: Arms writing model integration code frequently lack lazy initialization guards.
- **Recommendation**: Coding rules in Arm system prompt should enforce lazy initialization patterns for ML sessions, models, and network resources.

### 6. Arm Directory Sprawl
- **Symptom**: Multiple arms placed identical module names across new subdirectories (`deploy/skills.py`, `models/skills.py`, `skills.py`).
- **Root Cause**: Arms 7 (DevOps) and 1 (Model) default to scoped subdirectories rather than respecting the requested flat module layout.
- **Recommendation**: Conductor should restrict workspace domain roots during single-package missions unless explicitly requested.
